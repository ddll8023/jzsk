# 后端重构 - 参考文件清单

## 目的

在 `backendV2` 目录下创建全新的后端项目，**完全匹配前端(frontendV2)定义的API接口**，并遵循**规范文档/后端规范文档.md**的要求进行开发。

---

## 重构背景 **现状**：

-前端(frontendV2)已定义好API接口，但后端接口不匹配或未实现
- **目标**：重新编写后端代码，使API接口与前端完全一致
- **产出**：全新的后端项目 `backendV2`

---

## 二、数据库表结构（必须参考）

项目使用 **9个数据源**，通过 `@DS` 注解切换：

### 2.1 MySQL 数据源

| 数据源 | 库名 | 说明 |
|--------|------|------|
| `gcdd` | gcdd | 工程调度库 |
| `jcxx` | jcxx | 基础信息库 |
| `yjxx` | yjxx | 预警库 |
| `collector` | collector | 采集数据库 |
| `eb_database` | eb_database | 其他数据库 |

### 2.2 SQL Server 数据源

| 数据源 | 库名 | 远程地址 | 说明 |
|--------|------|----------|------|
| `dbo` | COLLECTOR | 111.4.68.108:1433 | 远程SQL Server |
| `zkxt` | ZKXT | 111.4.68.108:1433 | 闸控系统数据库 |

### 2.3 PostgreSQL 数据源

| 数据源 | 库名 | 远程地址 | 说明 |
|--------|------|----------|------|
| `pgsql` | dbaqjc | 111.4.68.108:5433 | 远程PostgreSQL |

### 2.4 表结构参考文件

#### MySQL 数据库
```
sql/jcxx.sql    # 基础信息库：user, role, authority, organization, department, person
sql/gcdd.sql    # 工程调度库：dict, dict_detail, inspection_records, maintence_record,
                 # warning_information, warning_indicator_setting, measuring_station,
                 # measuring_item, flood_plan, duty_schedule, duty_log 等
sql/collector.sql # 采集数据库：st_pptn_hour, st_river_r 等
sql/yjxx.sql    # 预警库：warning_indicator_setting, video_configuration
```

## 五、使用说明

1. **开发新模块时**，先在本文档中找到对应的前端API文件，理解接口需求
2. **创建实体类时**，在数据库表结构部分找到对应表，参考sql/jcxx.sql等文件
3. **编写业务逻辑时**，参考现有后端代码的业务实现方式
4. **编写代码时**，严格按照规范文档/后端规范文档.md的要求

---

## 六、注意事项

- 前端API定义的接口路径、请求方法、参数名称必须完全匹配
- 数据库使用 @DS 注解切换 jcxx/gcdd/collector/yjxx 四个数据源
- 代码必须遵循规范文档中的所有要求
