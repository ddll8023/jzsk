# Java 后端规范

> Java 通用开发规范由 Skill `java-spec` 承载；本文件只保留规范入口、模块索引和当前项目适配信息，避免与 Skill 内的分模块规则重复。
> `java-spec` 面向 Java 项目本身，不默认绑定 Spring Boot、MyBatis、JPA 或固定的 Controller/Service 分层；执行任务时根据仓库真实技术栈按需加载适配模块。

## 使用方式

Java 后端开发、审查或重构任务会触发 `java-spec`。Skill 会先检查 JDK、Maven/Gradle、框架、模块边界、公开契约、事务/并发模型和验证命令，再读取需要的 reference。

当前项目检测到 Spring Boot 和 MyBatis，因此相关任务还应按需读取 `07-spring-adapter.md` 与 `08-mybatis-adapter.md`。

## 全局速查

1. 先确认真实 JDK、构建工具、框架版本和公开契约，再写代码
2. Java 8 项目不使用 Java 17 语法、`record` 或 `jakarta.*`
3. 不把固定四层架构、Spring、Lombok、JPA、MyBatis 或 REST 当作所有 Java 项目的默认前提
4. 输入模型、领域对象、持久化模型和输出模型按真实边界区分，不直接暴露数据库实体
5. 业务边界负责规则和编排，数据访问边界负责查询和映射，协议边界负责输入输出
6. 异常只在能处理、补偿或转换的边界捕获，不空 catch、不丢失 cause、不重复记录
7. 文件、连接、流、线程池和事务必须有明确的创建、关闭、提交、回滚和取消责任
8. 分页、批量、重试、线程创建和外部 URL 必须有边界
9. 授权在服务端资源边界执行，敏感信息不得进入代码、日志或公开错误
10. 事务、并发和性能优化必须基于调用链与证据，不依赖形式化注解或固定模板
11. 优先复用项目已有公共基础设施，不新增第二套响应、错误码、配置或工具体系
12. 只报告实际执行过的格式化、编译、测试、静态检查和集成验证

## 当前项目适配事实

| 项目 | 当前配置 |
|---|---|
| JDK | Java 8 |
| 构建 | Maven，`backendV2/pom.xml` |
| Web | Spring Boot 2.6.2 + Spring MVC |
| 校验 | Spring Validation + `javax.validation` |
| 安全 | Spring Security + 自定义 JWT，无状态会话 |
| 数据访问 | MyBatis Spring Boot 2.2.1 + XML Mapper |
| 数据库 | MySQL、SQL Server、PostgreSQL，多数据源 |
| API 响应 | `ApiResult<T>`，成功业务码为 `200` |
| 分页 | `PageResultVO<T>`，字段为 `list/total/page/size/totalPages` |
| 配置 | `application.yml`、`application-runtime.yml`、`@ConfigurationProperties` |
| 观测 | SLF4J/Logback、`traceId`、Actuator |

上述内容是当前仓库事实，不是 Java 通用规则；项目升级或契约变化时应先更新事实，再调整 Skill 适配。

## 约定优先级

发生冲突时按以下顺序处理：

1. 用户本次明确要求
2. 仓库级指令与项目文档
3. `pom.xml`、配置、数据库/API 契约和验证配置
4. 同模块已有实现与公共基础设施
5. `java-spec` 及其按需加载的 reference
6. 通用 Java 风格和示例
