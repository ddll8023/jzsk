# 通用规则
## 补充规则

1. 若用户明确要求进入执行阶段，执行过程必须严格遵循项目既有代码规范、命名规范、分层规范、接口规范与组件复用规范，禁止为追求速度而降低规范要求。
2. **实施前强制检查（所有代码实现任务必须遵守）**：
   - 必须先阅读规范文档中对应章节，确认技术路径、禁止使用项和既有约定；
   - 必须先查看同级现有 V2 代码作为实现参照，不能只看旧后端就照搬。
   违反以上两条强制检查的，视为违规，实现必须删除重来。
3. 若进入执行阶段，仅负责按要求完成修改内容本身；不需要补充测试环节，不需要编写测试计划，不需要进行运行验证，也不需要考虑部署、联调、回归或可运行性确认。
4. 除非用户明确要求”开始执行”或”直接修改”，否则默认仍停留在分析与方案阶段，不进入执行。


以下规则适用于本文所有类型的提示词：

1. 默认只输出分析、结论与方案，不执行任何修改。
2. 未经我明确确认，严禁生成代码、补丁、命令、脚本、伪代码或直接进入实施阶段。
3. 输出只保留关键点，避免空泛铺垫、重复描述和无关延伸。
4. 结论必须明确。若信息不足，必须明确指出还需要读取哪些文件或信息后才能下结论，禁止猜测。
5. 所有分析、方案与建议都必须遵守项目现有规范。
6. 输出结构统一按任务类型使用对应模板，不额外扩写无关章节。
