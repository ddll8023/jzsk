# 前后端联调自动化测试设计

> 设计日期：2026-03-02

## 一、测试目标

使用 Playwright MCP 对智慧水利后端已完成模块进行前后端联调测试，验证：
- 认证模块（4个API）
- 角色管理模块（7个API）
- 用户管理模块（9个API）

## 二、测试方案

### 方案选择：模块顺序测试

按已完成的模块依次测试，每个模块独立验证。

**优势：**
- 与开发结构一致，问题定位清晰
- 模块独立，某个API失败不影响其他模块测试
- 测试报告结构化，便于追踪每个模块质量

**测试流程：**
```
环境准备 → 认证模块测试 → 角色管理测试 → 用户管理测试 → 结果汇总
```

## 四、测试执行流程

### 4.1 环境准备

**启动后端服务：**
```bash
cd backend/szy-new
mvn spring-boot:run > logs/app.log 2>&1 &
```

**验证服务就绪：**
- 检查8081端口是否监听
- 访问 http://localhost:8084 验证前端
- 使用 Playwright 打开登录页面

### 4.2 认证模块测试

**API清单：**
1. **POST /login** - 登录
   - 正常：admin01 / Jzsk@123456
   - 异常：错误密码、空用户名

2. **GET /user/info** - 获取用户信息
   - 正常：携带JWT Token
   - 异常：无Token、无效Token

3. **POST /user/updatePassword** - 修改密码
   - 正常：旧密码正确
   - 异常：旧密码错误、新密码格式错误

4. **POST /logout** - 登出
   - 正常：清除Token

### 4.3 角色管理测试

**API清单：**
1. **GET /role/list** - 获取角色列表
2. **GET /role/{id}** - 获取角色详情
3. **POST /role/save** - 新增角色
4. **PUT /role/update** - 更新角色
5. **DELETE /role/{id}** - 删除角色
6. **POST /role/assignMenus** - 分配权限
7. **GET /role/menuIds/{id}** - 获取角色菜单

### 4.4 用户管理测试

**API清单：**
1. **GET /user/list** - 获取用户列表
2. **GET /user/{id}** - 获取用户详情
3. **POST /user/save** - 新增用户
4. **PUT /user/update** - 更新用户
5. **DELETE /user/{id}** - 删除用户
6. **POST /user/resetPassword** - 重置密码
7. **POST /user/assignRoles** - 分配角色
8. **POST /user/status** - 启用/禁用用户
9. **GET /user/roleIds/{id}** - 获取用户角色

### 4.5 结果汇总

- 统计成功/失败数量
- 记录失败原因和后端日志
- 生成改进建议

## 五、异常测试场景

### 5.1 通用异常场景

适用于所有API：
- 无JWT Token访问受保护API
- 无效或过期Token
- 权限不足（使用普通用户访问管理接口）

### 5.2 认证模块异常

| API | 异常场景 |
|-----|---------|
| 登录 | 用户名不存在、密码错误、密码格式错误 |
| 修改密码 | 旧密码错误、新密码过于简单（少于6位）、新密码与旧密码相同 |

### 5.3 角色管理异常

| API | 异常场景 |
|-----|---------|
| 新增角色 | 角色名重复、角色编码重复、空角色名 |
| 更新角色 | 角色不存在 |
| 删除角色 | 角色已分配给用户、角色不存在 |

### 5.4 用户管理异常

| API | 异常场景 |
|-----|---------|
| 新增用户 | 用户名重复、邮箱格式错误、手机号格式错误 |
| 更新用户 | 用户不存在 |
| 删除用户 | 用户不存在、删除自己 |
| 重置密码 | 用户不存在 |
| 分配角色 | 用户不存在、角色不存在 |

## 六、测试数据与日志监控

### 6.1 测试数据策略

**使用现有数据：**
- 登录使用现有管理员：`admin01 / Jzsk@123456`
- 查询测试使用现有角色和用户数据

**临时测试数据：**
- 新增/更新/删除创建临时数据（如"测试角色"、"测试用户"）

**监控时机：**

**关注内容：**
- SQL执行错误
- 事务回滚
- 空指针异常
- 认证失败详情

**日志提取：**
```bash
tail -n 50 backend/szy-new/logs/app.log
```

### 6.3 数据验证

- 新增操作：查询验证数据已创建
- 更新操作：查询验证数据已更新
- 删除操作：查询验证数据已删除

## 九、风险与应对

| 风险 | 影响 | 应对措施 |
|-----|------|---------|
| 后端启动失败 | 测试无法进行 | 检查端口占用、日志排查 |
| 前端页面异常 | 无法操作 | 使用API直接测试 |
| 数据库连接失败 | API调用失败 | 检查数据源配置 |
| 测试数据冲突 | 测试结果不准确 | 使用唯一测试数据标识 |
