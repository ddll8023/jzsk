# 模块说明文档

## 1. 文档定位

本文档用于说明荆竹水库智慧水利系统的功能模块设计，重点回答“系统有哪些业务能力、各模块解决什么问题、模块之间如何协作、后续开发应如何定位功能边界”。

本文档不按照代码目录、类名或文件结构展开。代码组织、技术栈、目录职责请参考 `doc/项目结构文档.md`；具体开发约束请参考 `规范文档/后端规范文档.md`、`规范文档/前端规范文档.md` 和 `规范文档/uniapp开发规范.md`。

## 2. 系统功能定位

系统面向水库运行管理场景，围绕“看得见、查得到、能预警、可处置、留痕迹”组织功能。整体能力可分为四类：

| 能力类别 | 说明 | 典型模块 |
| --- | --- | --- |
| 运行态势展示 | 汇聚空间、监测、设备和预警信息，提供整体态势入口 | 一张图、水雨情、大坝安全监测、闸门监控、视频监测 |
| 监测与预警 | 采集或查询各类监测数据，按指标阈值形成预警信息 | 水雨情、大坝安全监测、设备监控、预警管理 |
| 业务处置闭环 | 对异常、巡检、养护、值班等事项进行记录、处理和追踪 | 现场检查、综合报表、设备故障历史、预警信息处理 |
| 基础支撑管理 | 维护用户、角色、字典、组织、站点、测项等基础数据 | 系统管理、基础信息查询、认证授权、资源下载 |

## 3. 端侧职责划分

| 端侧 | 功能定位 | 设计重点 |
| --- | --- | --- |
| PC 管理端 | 面向值班人员、管理人员和运维人员，覆盖系统主要管理与监测功能 | 信息密度、列表筛选、图表分析、处置操作、权限控制 |
| 移动端 APP | 面向现场巡检和移动查看，覆盖核心监测查看与巡检记录 | 快速登录、移动端查看、拍照上传、定位、巡检处理 |
| 后端服务 | 提供统一接口、认证、业务规则、多数据源查询、文件上传和定时任务 | 分层清晰、接口稳定、统一响应、业务逻辑集中在 Service |
| 外部/异构数据源 | 提供 GNSS、雨量、水位、闸门、渗压等监测数据 | 数据读取、格式归一、异常保护、任务调度 |

## 5. 认证与门户模块

### 5.1 模块定位

认证与门户模块负责用户进入系统前后的身份识别、令牌维护、页面入口组织和基础访问控制。它是所有业务模块的前置能力。

### 5.2 核心功能

- 用户登录：使用账号密码完成认证，后端签发 JWT，前端保存 Token。
- 当前用户获取：进入系统后可获取当前登录用户完整信息，用于顶部栏、个人信息和权限判断。
- 登录态校验：PC 端路由进入业务页面前校验 Token，未登录用户跳转登录页。
- 门户框架：PC 端提供侧边栏、顶部栏和内容区；移动端提供首页、功能、我的三个 Tab。
- 退出登录：清理本地 Token 与用户状态，返回登录入口。

### 5.3 设计边界

- 认证只负责“用户是谁”和“是否允许进入系统”，具体业务权限由系统管理模块中的角色、菜单和用户角色关系支撑。
- 登录页不承载业务数据查询，登录成功后才进入业务模块。
- 门户菜单用于组织业务入口，不应承载具体业务逻辑。

### 5.4 开发关注点

- 新增需要登录的页面时，应接入统一路由守卫。
- 新增用户相关功能时，应优先判断它属于认证模块还是系统管理模块。登录、当前用户、修改本人密码偏认证；用户维护、角色分配、重置密码偏系统管理。

## 6. 一张图模块

### 6.1 模块定位

一张图是系统的空间态势入口，以地图方式汇聚水库、测站、图层、预警和监测点信息，帮助用户从空间维度快速理解当前运行状态。

### 6.2 核心功能

- 地图底图展示：基于地图能力展示水库区域和周边空间信息。
- 图层管理：支持 WMS 图层加载、显隐控制和图例说明。
- 测站标注：展示 GNSS、雨量、水位、渗流量等站点或监测点标记。
- 站点弹窗：点击测站后展示站点名称、状态、最新数据等摘要信息。
- 预警展示：展示预警面板和预警详情，帮助用户从地图入口发现风险。
- 工程概况入口：提供水库或项目简介入口，与基础信息中的库区信息形成互补。

### 6.3 设计边界

- 一张图只做“汇聚展示”和“空间入口”，不直接承担各监测专题的完整分析能力。
- 趋势分析、分页历史、维护配置等深度操作应跳转或关联到对应业务模块。
- 地图站点数据来自各监测模块或基础信息，不在地图模块中重复维护业务主数据。

### 6.4 关联模块

| 关联模块 | 关联方式 |
| --- | --- |
| 水雨情管理 | 提供雨量、水位站点及最新数据 |
| 大坝安全监测 | 提供 GNSS、渗压、渗流量等测点数据 |
| 预警管理 | 提供预警信息、预警等级和详情 |
| 基础信息查询 | 提供测站、测项、预警设施和工程基础资料 |

### 6.5 开发关注点

- 新增地图点位时，应先确认点位是否已有业务主数据来源。
- 地图弹窗只展示摘要字段，避免把专题页的表格、筛选和复杂操作塞入地图弹窗。
- 图层控制、站点状态、预警详情应保持可独立扩展，避免互相耦合。

## 7. 水雨情管理模块

### 7.1 模块定位

水雨情管理用于查询和分析水库水位、河道水位、降雨等水文数据，是运行值班和防汛研判的基础模块。

### 7.2 核心功能

- 降雨查询：按时间范围查询小时雨量数据，支持图表和表格展示。
- 水库水位查询：按测站和时间查询水位数据，支持分页、列表和趋势图。
- 数据导出：前端支持将查询结果导出为 CSV 或表格文件。
- 日期快捷选择：提供默认日期范围和常用查询区间，提升值班查询效率。
- 移动端查看：移动端提供水位监测、雨量监测页面，展示当前值、累计值、趋势和历史记录。

### 7.3 设计边界

- 水雨情模块负责“数据查询和展示”，不负责预警判定本身。
- 水位、雨量超阈值后形成预警的逻辑由预警任务与预警管理模块负责。
- 水雨情原始数据通常来自外部水文库或采集库，本模块不直接维护测站主数据。

### 7.4 数据与交互关系

| 数据对象 | 设计说明 |
| --- | --- |
| 小时雨量 | 用于降雨趋势、历史查询、预警任务输入 |
| 水位数据 | 用于水位趋势、历史查询、预警任务输入 |
| 测站信息 | 作为查询条件和展示标签，由基础信息或外部库提供 |

### 7.5 开发关注点

- 查询接口应优先支持时间范围、测站编码和分页条件。
- 图表与表格应使用同一份查询条件，避免图表和表格口径不一致。
- 新增统计指标时，应明确它是展示统计、报表统计还是预警判定输入。

## 8. 大坝安全监测模块

### 8.1 模块定位

大坝安全监测模块围绕大坝运行安全数据展开，包括渗流压力、渗流量和地表位移等专题，用于辅助判断坝体安全状态。

### 8.2 核心功能

- 渗流压力监测：按测点查询渗压数据，展示水位高程、水位、温度、水压等指标。
- 渗流量监测：按测站查询渗流量数据，支持趋势图、分页表格和导出。
- 地表位移监测：查询 GNSS 位移历史数据和最新数据，支持统计卡片、图表和表格。
- 测点列表：提供渗压、位移等监测点选择能力。
- 最新值展示：提供各测点最新数据，用于一张图或移动端首页摘要。
- 移动端查看：移动端提供渗压监测、渗流量监测页面，支持测点选择、实时值、趋势和历史记录。

### 8.3 设计边界

- 大坝安全监测模块负责专题数据分析和展示，不负责基础测点配置的维护。
- 预警指标配置和自动预警落库由预警管理模块负责。
- GNSS 外部平台数据代理属于外部数据接入能力，大坝模块只消费其结果。

### 8.4 关键专题设计

| 专题 | 功能说明 | 重点展示 |
| --- | --- | --- |
| 渗流压力 | 反映测点水压、温度、水位等变化 | 实时值、指标切换趋势、历史表格 |
| 渗流量 | 反映量水堰或相关测站的渗流量变化 | 当前值、趋势折线、历史分页 |
| 地表位移 | 反映 GNSS 测站位移变化 | 最新位移、历史趋势、统计摘要 |

### 8.5 开发关注点

- 新增监测指标时，应先明确指标所属专题、数据来源、单位和展示粒度。
- 图表需要明确时间字段、数值字段和空值处理规则。
- 同一指标在 PC 端和移动端展示时，应保持名称、单位和时间口径一致。

## 9. 闸门监控管理模块

### 9.1 模块定位

闸门监控管理用于查看闸门实时状态和历史数据，为水库调度、运行值班和报表查询提供支撑。

### 9.2 核心功能

- 闸门实时状态查询：按闸门编码查询当前或最近状态数据。
- 状态卡片：展示闸门开度、状态、采集时间等关键指标。
- 数据表格：分页展示闸门数据明细。
- 历史报表：按时间范围查询闸门历史记录，支持导出。

### 9.3 设计边界

- 闸门模块负责闸门数据的查询和展示，不负责调度指令下发。
- 闸门报表是闸门历史数据的查询视图，不应与值班日志、综合报表混为同一业务对象。

### 9.4 开发关注点

- 闸门数据通常来自专门的闸控数据源，查询条件应围绕闸门编码和时间范围设计。
- 实时状态与历史报表可共享数据处理口径，但页面交互目标不同，前者强调当前状态，后者强调追溯和导出。

## 10. 视频监测模块

### 10.1 模块定位

视频监测模块用于接入现场视频资源，辅助值班人员远程查看现场画面，支持实时预览、历史回放和云台控制。

### 10.2 核心功能

- 实时视频预览：加载视频插件并展示指定摄像头实时画面。
- 历史回放：按时间范围查看历史录像。
- 云台控制：支持方向、缩放等控制动作。
- 插件资源管理：依赖浏览器侧视频插件和静态脚本资源。

### 10.3 设计边界

- 视频模块只负责视频查看和控制，不参与监测数据计算。
- 摄像头点位若要出现在地图上，应通过一张图模块统一展示入口。

### 10.4 开发关注点

- 视频插件通常对浏览器环境有要求，新增交互前需要明确插件能力边界。
- 视频控制操作应有明确的状态反馈，避免用户无法判断操作是否生效。

## 11. 设备监控模块

### 11.1 模块定位

设备监控模块用于监测 GNSS、水雨情、渗流渗压等设备的数据到报情况，发现设备未到报、网络异常或恢复事件，并形成可查询的故障历史。

### 11.2 核心功能

- 分类设备状态：按 GNSS、雨量/水位、渗流渗压分类展示设备到报状态。
- 状态汇总：统计在线、未到报、网络异常等数量。
- 自动刷新：PC 端定期刷新设备状态，便于值班人员持续观察。
- 故障记录：当设备状态异常时形成故障主记录。
- 故障事件明细：记录故障开始、状态变化、恢复等事件过程。
- 故障历史查询：按设备类型、状态、时间等条件分页查询历史故障。
- 故障恢复：设备恢复后记录恢复事件并更新故障生命周期。
- 历史清理：通过定时任务清理超期设备故障记录。

### 11.3 设计边界

- 设备监控关注“设备是否按预期到报”，不直接替代水雨情、大坝监测等业务数据分析模块。
- 设备故障记录是运维事件，不等同于业务预警信息。
- 设备状态判定可消费多类监测数据，但不应改变原始监测数据。

### 11.4 状态设计

| 状态 | 业务含义 |
| --- | --- |
| online | 设备或数据源正常到报 |
| offline | 设备在线但未按预期时间到报 |
| network_error | 查询数据源或外部接口时出现网络或访问异常 |
| recovered | 曾经异常的设备恢复到报后进入恢复状态 |

### 11.5 开发关注点

- 新增设备类型时，需要同时考虑状态查询、故障记录、事件明细、前端筛选和展示名称。
- 故障记录应体现生命周期，而不是每次异常刷新都生成一条重复主记录。
- 故障历史用于追溯，应保留故障开始时间、恢复时间、持续时长和事件变化过程。

## 12. 预警管理模块

### 12.1 模块定位

预警管理模块负责预警指标配置、自动预警判定、预警信息查询与解除，是监测数据向业务处置转化的核心模块。

### 12.2 核心功能

- 预警指标设定：维护监测类型、监测点、阈值、等级等预警规则。
- 指标选项：提供测点、监测项、绑定关系等下拉选项。
- 预警信息查询：按地点、状态、等级、类型、时间范围筛选预警记录。
- 解除预警：更新预警状态，记录解除时间并计算持续时间。
- 自动预警任务：定时读取水位、雨量、MCU、GNSS 等监测数据，根据阈值生成预警。
- 阈值判断：统一预警等级判断顺序和口径。
- 预警设施管理：维护预警广播、设施名称、位置、类型、状态等基础信息。

### 12.3 设计边界

- 预警指标是“判定规则”，预警信息是“判定结果”，二者不能混为一个对象。
- 预警设施属于基础业务设施，可在基础信息入口维护，也可服务于预警业务。
- 自动预警任务只负责按规则生成或更新预警，不负责前端展示交互。

### 12.4 典型预警流程

1. 业务人员在预警指标中配置监测点、指标类型和阈值。
2. 定时任务读取对应监测数据。
3. 阈值判断组件计算是否超阈值以及预警等级。
4. 若存在未解除同类预警，则进行去重或更新；否则新增预警信息。
5. 值班人员在预警信息处理中查看、筛选、解除预警。
6. 一张图展示未解除预警摘要和详情入口。

### 12.5 开发关注点

- 新增预警类型时，需要同时明确数据来源、指标配置字段、阈值判断方式、预警内容生成口径和前端筛选项。
- 预警去重应以监测点、监测类型和未解除状态为核心判断维度。
- 解除预警时应保留解除时间和持续时间，便于后续统计和追溯。

## 13. 现场检查模块

### 13.1 模块定位

现场检查模块覆盖巡检记录和维护记录，用于记录现场检查、异常发现、处理状态、图片资料和维修养护过程。

### 13.2 核心功能

- 巡检记录列表：按站点、异常情况、负责人、处理状态、日期范围筛选。
- 巡检记录详情：查看巡检时间、站点、负责人、异常、图片等信息。
- 巡检记录新增/编辑/删除：维护巡检过程资料。
- 巡检处理：将巡检异常标记为已处理。
- 巡检图片上传：上传巡检图片到对象存储并返回访问地址。
- 巡检导出：导出巡检记录数据，由前端生成文件。
- 维护记录管理：维护养护记录，支持查询、新增、编辑、删除和导出。
- 移动端巡检：支持巡检列表、筛选、新增、编辑、删除、标记处理、定位和图片上传。

### 13.3 设计边界

- 巡检记录关注现场检查过程和异常处理，设备故障历史关注设备到报生命周期，预警信息关注监测值超阈值，三者业务含义不同。
- 维护记录用于记录维修养护，不应替代巡检异常处理。
- 图片上传是现场检查的支撑能力，但图片本身不作为独立业务模块。

### 13.4 典型巡检流程

1. 巡检人员在移动端进入巡检记录。
2. 按站点或条件查看历史巡检记录。
3. 新增巡检记录，填写站点、类型、负责人、巡检日期、异常情况等信息。
4. 需要时获取定位并上传现场图片。
5. 若存在异常，后续通过处理操作标记为已处理。
6. 管理人员可在 PC 端筛选、查看、编辑、导出巡检记录。

### 13.5 开发关注点

- 新增巡检字段时，应同时考虑 PC 端表格、弹窗、移动端表单、详情展示和导出字段。
- 异常状态和处理状态应保持清晰关系，避免仅依赖文本描述判断是否已处理。
- 图片字段应统一保存访问 URL，避免前端与后端分别定义不同格式。

## 14. 基础信息查询模块

### 14.1 模块定位

基础信息查询模块维护业务运行所需的基础资料，是监测、预警、地图和巡检模块的业务底座。

### 14.2 核心功能

- 监测站点管理：维护站码、站名、水系、河流、行政区划、经纬度等信息。
- 测项信息管理：维护测项名称、编码、单位等信息，支持导出。
- 预警设施管理：维护预警设施基础信息，用于预警相关业务。
- 洪水防御预案：维护预案条目，支持增删改查和预览。
- 库区基本情况：展示水库工程概况、枢纽布置、运行要点等静态或半静态信息。

### 14.3 设计边界

- 基础信息模块维护“业务主数据”，不负责监测历史数据查询。
- 监测站点和测项是多个监测模块的公共基础，字段变更会影响查询条件、地图展示和预警指标配置。
- 库区基本情况偏展示资料，不应与动态监测数据混合维护。

### 14.4 开发关注点

- 基础资料新增字段前，应确认是否会被一张图、预警、移动端或导出能力使用。
- 用于下拉选项的数据应提供轻量选项接口，避免前端拉取完整分页列表后自行裁剪。
- 洪水防御预案当前偏前端资料管理，若后续转为后端持久化，应重新明确数据模型和权限边界。

## 15. 综合报表模块

### 15.1 模块定位

综合报表模块用于沉淀运行管理过程中的值班安排和值班日志，为日常值班、工作交接和历史追溯提供依据。

### 15.2 核心功能

- 值班安排：按日期范围查询，支持新增、编辑、删除、批量删除。
- 值班日志：按日期范围查询，支持新增、编辑、删除、批量删除。
- 列表分页：统一使用分页方式展示历史记录。
- 查询筛选：围绕日期、人员、关键内容等条件组织查询。

### 15.3 设计边界

- 值班安排面向计划，值班日志面向实际记录。
- 综合报表不直接统计监测数据，监测专题的图表和导出应留在各自业务模块。

### 15.4 开发关注点

- 安排和日志都属于运行管理记录，字段设计应保留人员、时间、内容和备注等追溯信息。
- 批量删除属于高风险操作，前端交互应有明确确认。

## 16. 资源下载模块

### 16.1 模块定位

资源下载模块用于提供巡检 APP 安装包和二维码，帮助现场人员获取移动端应用。

### 16.2 核心功能

- 展示 APP 下载二维码。
- 提供 APK 文件下载。
- 提供返回门户入口。

### 16.3 设计边界

- 资源下载只负责静态安装资源，不负责移动端版本管理、灰度发布或更新检测。
- 若后续需要版本管理，应升级为独立的移动端版本发布模块。

## 17. 系统管理模块

### 17.1 模块定位

系统管理模块用于维护组织、人员、用户、角色、菜单、部门和字典等系统基础管理能力，是认证授权、菜单展示和业务下拉选项的基础。

### 17.2 核心功能

- 用户管理：分页查询用户，新增、编辑、删除、分配角色、重置密码、修改当前用户密码。
- 角色管理：分页查询角色，新增、编辑、删除、分配菜单权限、查询角色菜单、提供角色选项。
- 菜单管理：维护系统菜单树或静态菜单视图，用于侧边栏导航和权限理解。
- 组织机构管理：维护组织机构信息。
- 人员管理：维护人员基本信息。
- 部门管理：维护部门信息。
- 字典管理：维护字典摘要和字典明细，提供扁平选项和树形选项。

### 17.3 设计边界

- 系统管理维护“系统运行基础数据”，不处理监测业务规则。
- 字典用于提供标准选项，不应承担业务记录存储职责。
- 角色菜单关系用于权限和导航，业务模块不应绕过系统管理自行维护权限关系。

### 17.4 权限关系设计

| 对象 | 说明 |
| --- | --- |
| 用户 | 登录主体，可分配一个或多个角色 |
| 角色 | 权限集合，可绑定菜单 |
| 菜单 | 页面入口和权限表达载体 |
| 用户角色关系 | 决定用户具备哪些角色能力 |
| 角色菜单关系 | 决定角色可访问哪些菜单或功能入口 |

### 17.5 开发关注点

- 新增后台页面时，应同步考虑菜单入口、角色授权和路由访问。
- 新增业务枚举时，优先判断是否应纳入字典管理，避免硬编码散落在多个页面。
- 用户密码相关功能应归口用户管理或认证模块，避免在其他模块重复实现。

## 18. 移动端业务模块

### 18.1 模块定位

移动端面向现场和移动查看场景，提供轻量监测查看、巡检记录和个人中心，强调快速访问、现场录入和离岗查看。

### 18.2 核心功能

- 登录：账号密码登录、表单校验、Token 持久化和登录后跳转。
- 首页：展示水库地图、图片轮播和基础信息。
- 功能中心：提供水位、雨量、渗压、渗流量、巡检等功能入口。
- 水位监测：展示当前水位、更新时间、趋势图和历史记录。
- 雨量监测：展示当前雨量、累计雨量、趋势图和历史记录。
- 渗压监测：支持测点选择、实时水压/温度/模数、指标切换趋势和历史记录。
- 渗流量监测：支持测站选择、当前渗流量、趋势图和历史记录。
- 巡检记录：支持列表、筛选、新增、编辑、删除和标记处理。
- 巡检表单：支持定位、图片上传和表单保存。
- 我的：展示当前用户信息并支持退出登录。

### 18.3 设计边界

- 移动端不覆盖 PC 端全部后台管理能力，只承载现场高频能力。
- 移动端和 PC 端共用后端业务接口时，应保持字段和状态口径一致。
- 移动端新增功能优先考虑是否适合现场操作，避免把复杂后台管理搬到小屏端。

### 18.4 开发关注点

- 移动端表单字段应与 PC 端业务对象保持一致，但交互可按移动场景简化。
- 图片上传、定位、分页加载更多等能力需要考虑弱网络体验。
- 监测图表应突出关键指标，避免在移动端堆叠过多筛选项。

## 19. 通用支撑能力

### 19.1 统一请求与响应

所有业务模块通过统一请求封装访问后端接口。后端接口应返回统一响应结构，前端通过请求拦截器处理 Token、401、分页数据和错误信息。

设计要求：

- 查询操作优先使用 GET。
- 新增、更新、删除、批量删除和复杂变更操作使用 POST。
- 分页数据保持统一分页结构，避免每个模块自定义分页字段。
- 业务错误由后端统一异常处理，前端展示明确提示。

### 19.2 字典与选项

字典用于统一维护业务枚举、下拉选项和树形选项。业务模块需要标准选项时，应优先复用字典能力或已有选项接口。

典型使用场景：

- 预警等级、预警状态、预警类型。
- 巡检类型、处理状态、异常情况。
- 人员、部门、角色、测站、测项等下拉选项。

### 19.3 文件与导出

文件能力主要服务于现场检查和资料下载：

- 巡检图片上传到对象存储，后端返回文件访问 URL。
- 巡检、维护、测项、闸门等模块可提供导出能力。
- PC 端部分导出由前端根据接口数据生成文件。

### 19.4 定时任务

定时任务用于自动预警和数据维护：

- 水位雨量检查任务：读取水雨情数据并触发预警判断。
- MCU 检查任务：读取相关监测数据并触发预警判断。
- GNSS 检查任务：读取外部位移监测数据并触发预警判断。
- 设备故障保留清理任务：清理超期故障历史。

设计要求：

- 任务应支持模块级或任务级开关。
- 任务执行应记录开始、完成、失败和耗时日志。
- 同一任务应避免并发重复执行。

### 19.5 多数据源

系统同时使用本地业务库和外部监测数据源。模块设计时应明确数据归属：

| 数据类别 | 典型模块 |
| --- | --- |
| 本地业务数据 | 系统管理、基础信息、预警管理、巡检、维护、报表、设备故障 |
| 水文监测数据 | 水雨情管理、预警任务 |
| 大坝监测数据 | 大坝安全监测、预警任务 |
| 闸门监测数据 | 闸门监控管理 |
| 外部 GNSS 数据 | 大坝位移、一张图、预警任务、设备监控 |

### 19.6 日志与链路

后端提供请求日志和 traceId 能力，模块开发应保证关键业务操作可追踪：

- 登录、创建、更新、删除、解除预警、故障恢复等关键动作应有明确日志。
- 定时任务应记录任务模块、任务编码和执行结果。
- 异常日志应包含关键业务参数，但避免记录密码等敏感信息。

## 20. 模块间关键关系

| 发起模块 | 依赖模块 | 关系说明 |
| --- | --- | --- |
| 一张图 | 水雨情、大坝、预警、基础信息 | 地图聚合多个业务模块的摘要信息 |
| 预警管理 | 水雨情、大坝、基础信息 | 使用监测数据和指标配置生成预警 |
| 设备监控 | 水雨情、大坝、外部数据源 | 使用数据到报情况判断设备状态 |
| 现场检查 | 基础信息、文件能力 | 使用站点等基础数据，上传现场图片 |
| 移动端业务 | 认证、水雨情、大坝、现场检查 | 复用后端接口提供移动端能力 |
| 系统管理 | 认证与门户 | 为登录、角色、菜单和用户信息提供基础数据 |
| 综合报表 | 认证与系统管理 | 记录值班人员、日期、日志等运行管理信息 |

## 21. 典型业务闭环

### 21.1 监测数据到预警闭环

1. 监测数据进入对应数据源。
2. 水雨情或大坝模块提供数据查询展示。
3. 预警定时任务读取监测数据。
4. 阈值规则判断是否生成预警。
5. 预警信息进入 PC 端列表和一张图展示。
6. 值班人员处理并解除预警。

### 21.2 设备故障闭环

1. 设备监控模块定期查询各类设备到报情况。
2. 发现未到报或网络异常后生成或更新故障记录。
3. 状态变化写入事件明细。
4. 前端展示当前状态和故障历史。
5. 设备恢复后记录恢复事件，故障生命周期结束。
6. 超期历史通过清理任务归档或删除。

### 21.3 巡检处置闭环

1. 巡检人员在移动端或 PC 端创建巡检记录。
2. 如有现场图片，上传到对象存储。
3. 管理人员在 PC 端查看、筛选和编辑记录。
4. 异常记录经过处理后标记为已处理。
5. 巡检记录可导出，形成线下存档或报表资料。

### 21.4 值班管理闭环

1. 管理人员维护值班安排。
2. 值班人员按安排进行日常监测和处置。
3. 值班过程形成值班日志。
4. 后续通过日期范围查询日志和安排，支撑交接与追溯。

## 22. 后续开发参考原则

### 22.1 模块归属判断

新增功能前先判断它属于哪一种能力：

| 问题 | 优先归属 |
| --- | --- |
| 是否是用户登录、Token、当前用户？ | 认证与门户 |
| 是否是地图上的汇聚展示？ | 一张图 |
| 是否是某类监测数据的查询和趋势分析？ | 对应监测模块 |
| 是否是超阈值规则和预警记录？ | 预警管理 |
| 是否是设备未到报、网络异常、恢复事件？ | 设备监控 |
| 是否是现场巡检或维护资料？ | 现场检查 |
| 是否是站点、测项、设施、水库资料？ | 基础信息查询 |
| 是否是用户、角色、组织、字典？ | 系统管理 |
| 是否是值班计划或日志？ | 综合报表 |

### 22.2 功能设计顺序

建议新增模块或功能时按以下顺序设计：

1. 明确业务对象：这个功能维护或展示的核心对象是什么。
2. 明确用户角色：谁使用，使用场景是 PC 端、移动端还是任务自动执行。
3. 明确状态流转：是否存在新增、更新、删除、处理、解除、恢复等状态变化。
4. 明确数据来源：来自本地业务库、外部监测库、对象存储还是静态资源。
5. 明确展示形态：列表、表单、图表、地图点位、弹窗、报表或移动端卡片。
6. 明确关联模块：是否需要字典、站点、测项、角色权限、预警或文件能力支撑。

### 22.3 文档更新规则

- 新增功能模块时，应同步更新本文档的模块说明。
- 若只是新增接口、页面或组件，但业务归属不变，应更新对应模块的核心功能或开发关注点。
- 若调整目录结构但业务能力不变，应优先更新 `doc/项目结构文档.md`，本文档只在功能边界变化时更新。
- 若新增数据库表或数据源，应同步更新数据库表使用清单和相关模块的数据说明。
