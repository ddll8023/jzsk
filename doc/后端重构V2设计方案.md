# 后端重构V2设计方案

## 1. 文档定位

本文档只用于说明后端 V2 重构的设计口径和边界。

本次 V2 不是在原项目上直接修改，而是在新建 `V2` 目录中重做。旧后端的作用是作为问题定位和逻辑参考来源，在 V2 中按新的规范重新设计，并根据需要做优化。

## 2. 重构前提

1. V2 在新目录中重做，原项目保留作为参考。
2. V2 对外接口对标前端真实使用的 API。
3. V2 接口规范只使用 `GET` 和 `POST`。
4. 如果当前前端存在 `PUT` 或 `DELETE`，则前端也需要同步调整。
5. V2 的逻辑实现只参考旧项目，不要求完全复用，允许结构优化和逻辑优化。
6. V2 重构范围不仅包含接口，也包含定时任务、数据同步、自动预警等非接口能力。

## 3. 重构范围

| 范围 | 说明 |
| --- | --- |
| 接口层 | 对标 `frontendV2` 真实使用的 API，重新设计 V2 接口 |
| 业务逻辑层 | 参考旧后端已有实现，必要时优化，不做机械搬运 |
| 定时任务 | 旧后端中的自动预警、数据同步等任务需要纳入 V2 范围 |
| 外部依赖 | 包括外部监测接口、数据采集来源、第三方调用方式 |
| 权限与资源 | 用户、角色、菜单、字典等基础支撑能力 |
| 数据处理细节 | 多数据源、几何点位、SQL Server 特殊处理、上传导出等 |

V2 重点涉及模块：

1. 系统管理
   - 用户
   - 角色
   - 菜单
   - 字典
2. 预警管理
   - 预警信息
   - 预警指标
   - 预警设施
   - 自动预警任务
3. 工程管理
   - 监测站点
   - 监测项
   - 防洪预案
4. 巡检与养护
5. 水雨情、大坝、闸门
6. 数据同步与外部采集任务

## 4. 设计原则

### 4.1 新目录重做

V2 独立建设，不在旧目录上做增量拼接。

### 4.2 接口统一规范

V2 只使用两种请求方式：

1. `GET`
   - 用于查询
2. `POST`
   - 用于新增、修改、删除、批量处理和特殊业务动作

说明：

1. V2 不使用 `PUT`
2. V2 不使用 `DELETE`
3. 如果前端现有调用不符合该规范，则前端必须同步调整

### 4.3 旧项目只作参考

旧后端只承担两类价值：

1. 作为问题定位来源
2. 作为已有业务处理经验来源

V2 不要求完全复用旧实现，允许：

1. 调整分层
2. 优化命名
3. 合并重复逻辑
4. 优化接口结构
5. 优化任务拆分方式

### 4.4 接口与任务同等重要

V2 重构对象不仅包括接口，还包括：

1. 定时任务
2. 自动预警
3. 数据同步
4. 外部接口采集
5. 配置与调度开关

### 4.5 遇到问题先追旧后端

V2 开发时遇到问题，不先在新项目里猜实现，而是先去旧后端找对应处理方法，再决定是否沿用、简化或优化。

## 5. 旧后端参考策略

| 问题类型 | 旧后端参考位置 | V2 处理原则 |
| --- | --- | --- |
| 几何点位处理 | `WarningInformationServiceImpl`、`InspectionRecordsServiceImpl`、`MeasuringStationServiceImpl` | 参考旧实现方式，在 V2 中统一封装 |
| 权限和缓存清理 | `UserController`、`RoleController` | 参考角色分配、菜单分配后的缓存处理逻辑 |
| 外部位移/监测聚合 | `DisplacementHistoryService` | 参考外部接口聚合方式，V2 中可优化参数和返回结构 |
| 自动预警规则 | `WarningAutoCheckTask` | 参考阈值判断和预警生成方式，V2 中按模块重构 |
| 水雨情采集逻辑 | `WarningAutoCheckTask`、相关 Mapper | 参考数据来源与最新数据查询方式 |
| 闸门 SQL Server 特殊处理 | `DgqServiceImpl` 及同类实现 | 参考 JDBC 兼容方案，V2 中视情况保留或收敛 |
| 上传与导出 | `InspectionRecordsController`、`MtenceRecordController` | 参考旧处理经验，V2 中统一规范 |
| 数据同步 | `DataSyncTask` | 参考同步职责和同步入口，V2 中重新规划任务职责 |

## 6. 定时任务纳入说明

旧后端已存在定时任务能力，主要涉及：

1. 数据同步
2. 自动预警
3. 外部数据采集相关处理

因此 V2 重构时，定时任务必须和接口一起纳入设计范围，不能只完成接口迁移，而忽略依赖任务才能成立的业务能力。

V2 对旧定时任务的处理方式只保留四种：

1. 保留
2. 合并
3. 重写
4. 废弃

具体任务清单和迁移状态放在进度文档中跟踪，不在本设计文档中展开。
