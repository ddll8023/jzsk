## 2. 当前阶段

当前已完成 V2 基础骨架阶段、D1 字典模块和 D2 用户角色模块落地，`backendV2` 已具备独立工程、公共基础层、鉴权入口、调度基础框架和用户角色管理能力；当前已完成 C1、C2、C3 契约冻结，并完成字典/字典详情/用户/角色模块 V2 化与菜单静态配置边界收口，D3 尚未开始。与此同时，已明确后续认证、权限及用户角色相关实现必须继续对齐旧项目数据库契约，逻辑允许优化，但数据库不可改造。

## 3. 已确认前提

| 项目 | 已确认内容 |
| --- | --- |
| 重构方式 | 在新建 `V2` 目录中重做，不直接在旧目录上修改 |
| 接口规范 | V2 只使用 `GET` 和 `POST` |
| 前端协同 | 当前若存在 `PUT`、`DELETE`，前端也需要同步调整 |
| 逻辑来源 | 旧后端逻辑必须作为实现参考来源，允许在分层和流程上优化 |
| 数据库边界 | 必须完全复用旧项目既有数据库、表结构、字段语义和数据来源，不为 V2 另建平行业务库表模型 |
| 重构范围 | 不只包含接口，也包含定时任务、数据同步、自动预警等内容 |

### 8.3 V2 接口规范冻结结果

| 维度 | 冻结结果 |
| --- | --- |
| 统一前缀 | 全部 V2 接口使用 `/api` |
| 资源命名 | 小写英文复数 + `kebab-case` |
| 分页查询 | `GET /api/{resources}/page` |
| 普通列表 | `GET /api/{resources}/list` |
| 详情查询 | `GET /api/{resources}/{id}` |
| 新增/修改/删除 | `POST /create`、`POST /update`、`POST /delete` |
| 批量动作 | `POST /batch-delete` 等动作型路径 |
| 选项接口 | `GET /options`、`GET /options/tree`、`GET /options/list` |
| 导出与上传 | `GET /export`、`POST /upload` |
| 分页参数 | 统一为 `page`、`size` |
| 分页返回 | 统一为 `list/total/page/size/totalPages` |

### 8.4 DTO/VO 范围冻结结果

| 范围 | 冻结结果 |
| --- | --- |
| 写接口入参 | 全部使用 DTO |
| 查询入参 | 列表/分页统一使用 QueryDTO，分页复用通用分页 DTO |
| 返回对象 | 全部使用 VO，统一包裹在 `ApiResult<T>` 中 |
| 分页返回 | 统一使用 `PageResultVO<T>` |
| 删除/批量删除/分配类动作 | 使用独立动作 DTO，不再依赖 `DELETE /{id}` 语义 |
| 强制模块 | 认证、系统管理、预警、工程、巡检养护、报表、水雨情/大坝/位移等全部纳入 |
